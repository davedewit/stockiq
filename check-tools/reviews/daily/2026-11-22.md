## Faults (first)

### 1. Every weekend, the daily screener pages count Friday's US session twice (sure)
- **What:** the daily run happens at about 17:50 UTC, which is the middle of the US trading day (and Canada's, Brazil's,
  Mexico's). On a weekday that is fine: each run shows that day's session, part-way through. But on Saturday the run sees
  Friday's *closing* prices, which differ from the Friday afternoon prices seen the day before, so the script takes them for a
  new session.
- **Evidence** (the kept state files, S&P 500 page, "days in the top 10"):
  - Fri 13 Nov: MRNA 10, CNC 15, CRL 7. Sat 14 Nov: MRNA 11, CNC 16, CRL 8. Sun 15 Nov: unchanged. Mon 16 Nov: MRNA 12.
  - Fri 20 Nov: MRNA 16, CRL 13, HUM 12. Sat 21 Nov: MRNA 17, CRL 14, HUM 13.
  - So each weekend adds one session that never traded. The hub on Saturday also called CNC the S&P 500's "new" leader and showed
    "▼ 2 pts since last update": that is Friday afternoon compared with Friday's close, not one session with the next.
- **Where:** `update_screener_pages.py` lines 375-436 (`session_sig` is a fingerprint of the prices; `same_session` treats a
  different fingerprint as a new session). It was built on 31 Oct for the case of unchanged prices; prices that change *within*
  one session (a mid-session run, then the close) are not covered. The cap on weekdays since 23 Oct (line 432) hides it once a
  count reaches 21.
- **Also coming:** US Thanksgiving is Thursday 26 Nov. Thursday's run will see Wednesday's close against Wednesday afternoon and
  count Wednesday twice in the same way.
- **The change:** the workers send the date of each share's last session (the last price bar's date on the exchange's own
  clock: one new field; `workers/prove.py` to show nothing else moves), and the pages count a new session only when that date
  moves on. Until that is built, a weekend run can simply treat the last weekday's figures as the same session. A daily check in
  `site_audit.py` would catch it: on a weekend, or after a market holiday, no "days in the top 10" may rise.
- Proposal **#36** on the Admin page (recommended yes; best built with #33, which changes the same script).

### 2. A buy line contradicts itself (sure)
- **What:** in "What it has done", Fri 20 Nov 21:40: *"Bought MRNA with $1,997. Taken by rank, not by the AI model (a trial …):
  rank 7 in S&P 500 … (S&P 500 rank 7, score +2.7; chosen by the AI model)"*. Every second share buy since the rank-pick trial began
  (23 Oct) reads like this.
- **Where:** `stockiq-ai-trader` lines 3096-3097 choose the words "chosen by the AI model" from where the shortlist came from
  (`source == 'ai'`), not from who chose. The record underneath is right (line 3071 sets the buy's `chosen` to "rank"), so the
  trial's figures are not affected; only the words users read are wrong.
- **The change:** use the buy's own `chosen` for the words, a test in `ai_trader_test.py`, and a rule in `clarity_check.py`
  that flags any line saying both "not by the AI model" and "chosen by the AI model" (it passed today: its tests do not look for a
  contradiction inside one line).
- Proposal **#37** (recommended yes).
